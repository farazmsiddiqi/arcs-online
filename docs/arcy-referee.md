# Arcy: shared table chat and rules referee

Players open **Chat @arcy** and mention `@arcy` to ask a question. Ordinary messages are exchanged between authenticated seats without calling a model. All referee answers are public to that table. The drawer remains separate from the guided turn flow, supports keyboard and pointer resizing, keeps drafts when closed, groups supporting excerpts by source, and reconnects to saved messages.

## Evidence and context

The server indexes a pinned publisher corpus from the official searchable Arcs rules library. `data/arcy-rules.json` records the exact source bundle URL, SHA-256, retrieval date and publisher revision. Base rules, Leaders & Lore, Fine Print, glossary and applicable publisher FAQs/errata are included; campaign-only setup and campaign chapters are excluded from retrieval. Existing card text and the bundled card FAQ/errata are indexed separately. Some shared publisher passages mention campaign differences; the agent is explicitly limited to base play.

Retrieval uses BM25 with conservative synonym expansion, exact card-name boosts and section-level chunks that keep procedures and exceptions together. It initially retrieves the question and recent conversation, includes active players' card abilities and their clarifications, and always supplies rules hierarchy, piece limits, turn etiquette and the table's split-discard variant. GPT can call the read-only `search_rules` tool for cross-references. This is retrieval-augmented generation without a hosted vector database or an embedding-service dependency.

The default model is `gpt-6-astra` with medium reasoning, via the [Responses API](https://developers.openai.com/api/docs/guides/text). Each answer receives a separate review pass against the question, sources and the same public snapshot. Both passes use [structured output](https://developers.openai.com/api/docs/guides/structured-outputs). The final response is checked for known source IDs and exact supporting quotes from retrieved text. Citation URLs come from the corpus, never from model-generated links. React renders all player/model prose as escaped text.

`refereeContext()` uses a spectator view plus an explicit field allowlist. It includes players, public pieces and resources, face-up cards, lead/declarations, initiative, chapter/round, current actor/activity, public battle context, ambition counts, supply, map control, and recent/current-turn public events. It excludes all hands (including the asker's), face-down identities, deck order, RNG, pending stacks, rollback snapshots, seat credentials, and hosting configuration. The snapshot labels the response; if play has moved on, the UI says **Earlier position**. Engine behavior is context, not authority: Arcy must report a discrepancy rather than invent a rule to justify it.

The agent distinguishes a supported ruling, public-state context, a missing-detail question and an unsupported request. It is instructed to handle hypotheticals separately, remain impartial, ignore player-supplied instructions to change its role, and avoid asking for public disclosure of private hands. It has no game-action, timer, shell, filesystem, external search or network tools. No result is applied to the game.

## Fair play and references

Arcy is a referee, never a coach. A separate structured scope check runs before the answer model receives the board; requests for move selection, rankings, tactical hints, scoring optimization or optimal dice return a fixed server-authored refusal. The independent answer review also checks for strategic advice in every output field and can withhold the response even if the input gate allowed it. Missing review flags fail closed. Neutral legality, mandatory consequences of a player-selected action, public facts and dice-face probabilities remain in scope. This is a layered model-based boundary, not a mathematical guarantee against every possible prompt.

Typing `@` opens a filtered picker grouped into referee, players and game references. Arrow keys navigate, Enter/Tab insert, and Escape dismisses. References are resolved against known seats and public snapshot fields; they cannot expose hidden hands. Reserved names receive stable player-number aliases. Only an `@arcy` mention requests an AI reply; mentioning another player or `@board` alone remains ordinary shared chat. The UI highlights known mentions and renders sources in one expandable section per answer.

## Persistence, failures and cost controls

Chat uses separate SQLite tables. Messages and pending replies are inserted together; model completion updates only the answer row. It never saves the captured room, avoiding stale-state overwrites while other players take turns. Client request IDs are idempotent, including failed-network retries. Chat changes do not alter game revisions or undo history. The newest 100 messages are returned with room state; earlier messages are available through an authenticated cursor endpoint.

The server limits messages to 1,500 characters and 20 per seat per minute. Referee requests allow one concurrent question per table and four per process, with a 15-second per-seat cooldown. Persistent rolling 24-hour quotas default to 60 per table / 300 per server, including retries. A request first makes one scope-classification call, then at most four retrieval/answer calls and one independent review call; each has a 5,000-token output cap, and the whole request has a 90-second deadline. Configure provider-side budgets as well: question counts are not dollar limits.

`OPENAI_API_KEY` stays server-side. Only explicit mentions send the question, recent shared chat and public position to OpenAI; `store:false` is set on each call, which does not eliminate the provider's own retention policies. Conversations and synthetic evaluation output are never committed. On a provider failure, timeout or invalid citation, players see a retryable failure rather than an unverified answer. A restart marks interrupted requests as failed rather than replaying them automatically. Only the asker or host can retry, and retry captures the current position. Gameplay and ordinary chat work with no API key.

## Verification and maintenance

Release verification (2026-10-17): the full 639-test suite and production build passed. Sixteen synthetic scenarios were also evaluated against the live `gpt-6-astra` API and their actual answers reviewed, including the Elder/Galactic Rifles interaction, zero-marker pips, empty resource supply, scoring ties, raids, Prelude timing, ambiguous questions and hidden-hand prompt injection. The hidden-hand refusal correctly used the public-context status; the evaluation's allowed statuses were updated accordingly. These are sampled checks, not exhaustive proof of all possible rulings.

- Offline tests cover retrieval, exact citation validation, bounded tool calls, independent review, private-state exclusion, message idempotency, budget persistence, authorization, cross-table isolation, origin checks, realtime delivery, restarts and concurrent gameplay.
- `scripts/arcy-eval.mjs` is an opt-in paid evaluation against synthetic states. It covers rule/card exceptions, scoring ties, resource timing, control, raids, ambiguous questions, campaign scope, prompt injection and current-table context. Source/status checks help catch regressions; read the actual answers before treating a run as passed.
- The reference library is pinned rather than silently updated during play. To refresh it, run `node scripts/sync-arcy-rules.mjs [publisher-bundle-url]`, review the resulting corpus diff, and rerun the tests/evaluations. The importer parses literal AST nodes and never executes downloaded JavaScript. Structural changes fail closed.

Exact quotations demonstrate that cited text exists; they do **not** prove that an inference is correct. Independent model review and tests reduce mistakes but cannot guarantee them away. Official publisher rules remain authoritative. There is no claim that Arcy resolves every possible scenario perfectly.


Chat update verification (2026-10-17): 655 automated tests and the production build passed. Eleven live API cases covered rules, mention context, mandatory consequences, and six adversarial coaching requests; all coaching requests returned the fixed refusal. Three further live cases verified that Arcy identifies and explains the actual public draft pool, resolves the terse follow-up “the leader opts”, and refuses to choose a leader. Actual answers were reviewed, not just their source IDs.

The snapshot includes the shared draft Leader/Lore pool, names, choosing player, and the matching publisher card texts in retrieval. It never includes the remaining undrawn Lore reserve. `@draft` references this pool. Draft explanations describe abilities without ranking choices.

Replies form persistent shared threads. Use **Reply in thread / Open thread**; Arcy automatically responds to follow-ups in a thread it has joined, without another mention. Ordinary player-only threads stay ordinary chat until someone invokes Arcy. Each ruling gets its own thread history (original question plus recent replies) and a fresh public board snapshot. Threads remain visible to all seated players; they are not private AI conversations. Parent IDs are validated within the authenticated room; pagination keeps the original question and migrations preserve existing messages. Switching threads retains unsent drafts during the session.
